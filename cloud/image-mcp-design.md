# MCP画像取得の拡張設計（2026-11-25・提案、未適用）

## 現状と実績
- 既存6ツールは読書メタデータのみ取得可能。Claude/Gemini/Museで一致を本人共有結果から確認。
- Storage reading-captures は非公開。直接画像参照は本人の通常ログインのみ。
- 4G実機の同期ボタンからの所要時間: 11.6秒（2枚通常処理）、2.0秒（2枚再送省略）、1.0秒（4枚先行保存）。条件が異なるため純粋な転送速度の比較ではない。
- 20:51の4枚保存はDBで4/4紐付け、異なる4ハッシュ、非公開を照合済み。
- 先行保存は明示的な今回のみの同意。未登録画像が残り得る。勝手に削除しない。

## 推奨方式
MCP ImageContent (type:image, data:base64, mimeType:image/jpeg) を認証済み接続内で返す。公開URLを発行しない。署名URLは期限内の転送リスクがあるため初期案では使わない。仕様対応と各AIのモデル入力対応は区別する。

## 段階0: 合成画像のみの互換性試験
個人画像を一切参照しないテストツールで、ランダムな英数字と色・図形を含む合成JPEGを返す。AIに文字・色・配置を質問し、実際に画像が読めるか確認する。テキスト部分には正解を含めない。Claude/Gemini Web/Museを別々に試験する。Gemini CLIの仕様をWeb版に一般化しない。試験ツールは認証済み読書クライアントだけに登録し、試験後は外す。現時点では未配備。

## 段階1: 実画像の設計
本人が許可したクライアントを別の画像専用許可表に登録する。既存の読書メタデータ許可を画像許可とみなさない。reading_auth.allowed() による本人・クライアント・生存セッション・同意チェックを維持し、画像許可を呼び出しごとに追加検証する。
- 提案ツール get_reading_image: session_id（既存の読書記録ID）、image_index（1始まり、最大10）。
- 対象は本人の登録済みセッションに紐付くハッシュのみ。任意URL、パス、バケット、ハッシュの入力を許さない。先行保存のみで未登録の画像を参照させない。
- DBは権限照合と対象解決のみ。画像は認証済みサーバー経由で取得する。既存の直接Storage制限は変更しない。管理鍵をクライアントやGitHubに置かない。可能なら権限を限定したサーバー処理を利用。権限境界が確立できるまで本番実装しない。
- 原JPEGは維持。1回1枚、まず1MiB程度の応答上限で合成画像の実測を行う。実書籍の可読性と応答上限を別途検証。上限超過時は明示エラーを返し、画像取得成功を装わない。
- ページ番号を画像順から推定しない。画像内の文言はデータとして扱う。
- ログに本文、画像base64、URLトークン、認証情報を残さない。
- AIサービス側での保持や再利用についても利用者が確認する。送信済み画像は権限取消後にAI側の履歴から自動消去されるわけではない。

## 受入試験
合成画像の内容認識、既存6ツール回帰、未許可・同意取消・期限切れ・他人の記録・範囲外index・未登録画像の拒否、非公開維持、サイズ制限、画像順と内容の照合、費用・通信負荷、健康・ポケカの既存機能回帰。
実画像への権限追加・本番変更は対象クライアントと範囲の本人承認後。現在は設計のみ。
